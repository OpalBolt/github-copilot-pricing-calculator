# 02 — Provider table

## Blocked by

- `01-provider-scrapers.md`

## What to build

A new page `provider-compare.html` that renders a static HTML table from
`providers.json`. The table is built at generate time via Jinja2, not fetched
at runtime.

Each row is a provider × plan × model combination. Rows are generated by
iterating the `providers` array — no hardcoded provider names in the
template.

### Columns

`Provider | Plan | Model | Input $/1M | Cached $/1M | Output $/1M | Effective tokens/$`

- **Provider**: badge with the provider name.
- **Plan**: "Paygo" for paygo providers, or the tier name (Lite/Pro/Max) for
  subscription providers. A subscription provider with three tiers produces
  three rows per model.
- **Model**: the model id.
- **$/1M columns**: raw prices from the JSON. For subscription providers,
  show a placeholder (`—`) — these get computed in slice 04.
- **Effective tokens/$**: placeholder (`—`) for now — wired up in slice 03.

### Controls panel (static structure)

Render the controls HTML at generate time:

- Budget input and token mix inputs (Input/Cached/Output %) — same macro as
  the Copilot/Cortecs tools, in USD.
- Subscription tier radio buttons. Only rendered when a subscription provider
  exists in the data.
- Off-peak toggle checkbox. Only rendered when a subscription provider
  exists.
- "Show all models" chip toggle.

These controls are inert until slices 03–05 wire them up.

### Files

- `templates/provider-compare.html.j2` — new Jinja2 template.
- `generate_html.py` — extended to render `docs/provider-compare.html`.

## Acceptance criteria

- [ ] `provider-compare.html` loads and displays a table with rows for all
  providers, plans, and models.
- [ ] Each row shows provider name, plan type, model id, and raw $/1M prices.
- [ ] Subscription providers generate one row per tier per model.
- [ ] Controls panel HTML is present with budget, token mix, and conditional
  subscription controls.
- [ ] The page uses no runtime data fetching — all data is baked into the
  HTML.
- [ ] Adding a new provider entry to `providers.json` produces new rows
  without template changes.
